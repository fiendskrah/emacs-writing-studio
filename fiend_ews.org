Emacs users have developed and shared thousands of packages with the rest of the community. This part of the configuration sets the essential elements to load and install packages from the MELPA archive and the default ELPA repository.

#+begin_src elisp :exports none

This configuration heavily relies on John Wiegley's Use-Package. This package makes installing and configuring packages with a standardised and easy-to-read method easier. Software developers call such a tool 'syntactic sugar', syntax designed to make code easier to read or write, making the language "sweeter" for humans [cite:@landin_1964].

The Use-Package system consists of a set of statements between parenthesis, which is a macro. In its simplest form, it is something like ~(use-package <package-name>)~. The code can also contain one or more sections to set various options. The =:custom= section in the second Use-Package macro sets three variables. Any missing package is automatically installed from its online source, and the source code is compiled to speed up Emacs. Compilation warnings are kept to a minimum so as not to scare beginning users with log files.

#+begin_src elisp :exports none
  ;; Package Management
#+end_src
#+begin_src elisp
    (require 'package)
      
  (setq package-archives
        '(("melpa"  . "https://melpa.org/packages/")
          ("org"    . "https://orgmode.org/elpa/")
          ("gnu"    . "https://elpa.gnu.org/packages/")
          ;; fiend - was missing here even though it's referenced in
          ;; package-archive-priorities below - package-install would have
          ;; had no idea where "nongnu" pointed. Needed for org-contrib.
          ("nongnu" . "https://elpa.nongnu.org/nongnu/")))
    ;; fiend - setting preference for melpa
    (setq package-archive-priorities '(("melpa"  . 100)
    				   ("gnu"    . 50)
    				   ("nongnu" . 0)))

    (package-initialize)
    
    (unless package-archive-contents
    (package-refresh-contents))

  ;; Use-package config
(unless (package-installed-p 'use-package)
  (package-install 'use-package))

(require 'use-package)

(setq use-package-always-ensure t
      package-native-compile t
      warning-minimum-level :emergency)
#+end_src

To read the finer details of the Use-Package macro, read the manual with =C-h R use-package=.

The ~ews-missing-executables~ function checks if external software is available on your system. Emacs writes a message in the minibuffer if any recommended tools are missing. You can jump to the Messages buffer with =C-h e= to review the output. Emacs will function normally when this software is unavailable, but some features might not work.

The input for this function is a list, a series of strings between parenthesis that starts with a tick symbol. This symbol prevents Emacs from confusing the list of data with a function. In this example, the list also contains other lists.

This function checks whether all these packages are available on your system. For software in a nested list, such as =("convert" "gm")=, only one of them has to be available, as these programs are alternatives for the same functionality.

*Fonts*
Explicit families, all bundled with macOS (nothing to install). Families
only, no :height, so sizes stay as they were. Change live with
=M-x set-face-font= (face variable-pitch or default; every buffer, until restart) and resize
globally with =C-x C-M-+= / =C-x C-M--=. mixed-pitch follows the
variable-pitch face, so prose updates with it.
#+begin_src elisp
  (set-face-attribute 'default nil :family "Menlo")
  (set-face-attribute 'fixed-pitch nil :family "Menlo")
  (set-face-attribute 'variable-pitch nil :family "Avenir Next")

  ;; SPC t f: pick prose/code, then an installed family. Until restart.
  (defun fiend/set-font (faces family)
    "Set FAMILY on FACES globally (prose = variable-pitch, code = default)."
    (interactive
     (let ((target (completing-read "Font for: " '("prose" "code") nil t)))
       (list (if (string= target "prose") '(variable-pitch) '(default fixed-pitch))
             (completing-read (format "%s font: " target)
                              (seq-remove (lambda (f) (string-prefix-p "." f))
                                          (delete-dups (sort (font-family-list) #'string<)))
                              nil t))))
    (dolist (face faces)
      (set-face-attribute face nil :family family))
    ;; mixed-pitch snapshots font families buffer-locally when enabled,
    ;; so re-toggle it wherever it's on to pick up the new family.
    (dolist (buf (buffer-list))
      (with-current-buffer buf
        (when (bound-and-true-p mixed-pitch-mode)
          (mixed-pitch-mode -1)
          (mixed-pitch-mode 1)))))
#+end_src

*** Configure text modes
Emacs is principally designed for developing computer code, so it needs some modifications to enable writing text for humans. Firstly, we hook Visual Line Mode to Text Mode. Visual Line mode wraps long lines to the nearest word to fit in the current window.

By default, Emacs does not replace text when you select a section and start typing, which is unusual behaviour when writing prose. The =:init= section enables a more common default so that selected text is deleted when typed over. The =:custom= section enables the page-up and page-down keys to scroll to the top or bottom of a buffer. This section also redefines the way Emacs defines a sentence (section [[#sec-count]]). The last variable saves any existing clipboard text into the kill ring for better operability between the operating system's clipboard and Emacs's kill ring.

RET should behave differently depending on Evil state: in Insert state, a plain newline like always; in Normal/Motion state, follow the link at point. org-return-follows-link (tried first, then reverted) is the wrong lever for this - it's a single global switch org-return itself consults, so turning it on made RET follow links in Insert state too, which is why it fired even mid-typing. It also deferred to org-file-apps for *how* to open a directory link, which on this machine resolves to the system file manager rather than Dired - hence Finder opening instead of Emacs.

Per-state binding fixes both at once: Insert state never gets touched, so it falls through to org-mode-map's own RET (org-return, plain newline, unconditionally). Normal/Motion state gets an explicit override - same precedence pattern as the org-agenda RET fix - that calls org-open-at-point with the "force in Emacs" prefix-arg behaviour (=C-u C-c C-o=, i.e. dired for directories) instead of leaving the how-to-open decision to org-file-apps/the OS.

#+begin_src elisp :exports none
  ;; RET: follow link in Normal/Motion, plain newline in Insert
#+end_src
#+begin_src elisp
  (defun fiend/org-open-at-point-in-emacs ()
    "Follow the link at point, forcing it open inside Emacs
(e.g. Dired for a directory) instead of deferring to org-file-apps
or an external/system application."
    (interactive)
    (org-open-at-point '(4)))

  ;; This section tangles early in init.el, well before (use-package evil
  ;; ...) further down - a plain (with-eval-after-load 'org ...) here fires
  ;; as soon as Org loads (which is immediately, a few lines up), which is
  ;; before Evil exists yet. That's a void-function error on
  ;; evil-define-key, and since it's uncaught, everything later in init.el
  ;; never runs - including the dashboard startup-buffer setup and the
  ;; general.el leader-key (SPC) bindings. Confirmed cause of both symptoms
  ;; ("dropped into scratch" + "SPC doesn't work") after tangling the
  ;; previous version of this block. Nesting under 'evil too defers the
  ;; whole thing until *both* are loaded, regardless of which finishes
  ;; loading first or where either block physically sits in the file.
  (with-eval-after-load 'evil
    (with-eval-after-load 'org
      (evil-define-key '(normal motion) org-mode-map
        (kbd "RET") 'fiend/org-open-at-point-in-emacs)))
#+end_src

The Org Fragtog package is similar to Org Appear but for LaTeX snippets. It automatically toggles Org mode LaTeX fragment previews as the cursor enters and exits them. By default, the text is small and can become unreadable when changing between dark and light themes.

The =org-format-latex-options= variable controls the way Emacs presents fragments. This variable is a list with properties such as colours and size. The =plist-put= function lets you change options in the list. The foreground and background are set to take the same colour as your text. If you change from dark to light mode or vice versa, you should evaluate the ~org-latex-preview~ function (=C-c C-x C-l=) to change the preview images.

- =SPC p f= "file in existing note" - cuts the subtree at point and files
  it into an existing pkb note as a brand-new H1, inserted at the very top
  of the file and tagged =:new:=. First attempt at this nested it as a
  child of the note's existing H1 (last child, then first child via
  =org-reverse-note-order=) - still one fold away from invisible either
  way. A standalone top-level heading is the first thing on screen the
  next time the note is opened, no expanding required. =:new:= marks it as
  freshly landed and not yet triaged into the note's real structure - a
  natural companion to task #11 (the weekly review) later: "clear every

- =SPC p n= "new note" - =fiend/pkb-extract-subtree-to-note= cuts the

=pkb/= at the denote-directory root - both of these commands are pkb-only
by design, bibliographic notes still go through citar-denote as before.
